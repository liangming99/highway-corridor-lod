# E2E 与卡死修复 · 2026-10-17

对象：G72 泉南高速桂林—鹿寨段。环境：Apple M5 · ANGLE Metal · 1440×900 · 无头浏览器。

## 现象

长时间漫游后页面冻结，主线程无响应。900 km/h 时 5 秒内即复现。

## 根因（三个叠加）

1. **槽位死锁**：图集槽位耗尽后，派发循环在候选之间无限轮转，主线程被独占。
2. **生产快于消费**：Worker 产出瓦片的速率高于主线程建面速率，`ready` 队列与 ImageBitmap 无上限堆积。
3. **整张图集上传**：2080² 画布每次 `needsUpdate` 触发整张上传，单次造成秒级长任务。

## 修复

| 问题 | 处理 |
| --- | --- |
| 槽位死锁 | 候选轮转最多一遍即退出；新增槽位压力淘汰（先淘汰不需要的，再淘汰离相机最远的），并设常驻下限避免画面空掉 |
| 生产快于消费 | `ready` 队列达上限即丢弃并 `bitmap.close()`；积压时暂停派发；页面隐藏时不派发 |
| 整张上传 | 每层一张小图集（1040–1560 px），每帧最多上传一张 |
| draw call 偏高 | 结构物由 66 个网格合并为 10 个；地面标记环合并为 1 个 |

## E2E 结果

脚本：`tools/e2e-soak.mjs`（持续 200 秒 @ 900 km/h，每 5 秒采样）。

| 指标 | 结果 |
| --- | --- |
| 采样次数 | 40 / 40 |
| JS 报错 | 0 |
| 常驻瓦片 | 中位 23，最低 20，最高 49 |
| 堆内存 | 中位 54.7 MB，峰值 84.6 MB（GC 后回落） |
| 绘制调用 | 12–17 |
| 最长长任务 | 851 ms |
| 点选详情 | 正常（洛清江特大桥，4 项指标，健康度 97） |
| 工单提交 | 正常（累计 6 条） |

修复前同一脚本在 5 秒内冻结、零采样：`e2e-soak.json` 记录为 `stage: failed`。

## 未解决

- 最长长任务仍有 851 ms，慢帧归因记录里没有对应项，说明它发生在 rAF 循环之外的合成/GC 阶段。可以接受，但还没定位到具体调用。
- 900 km/h 下队列长期积压约 100–140，属于「调度跟不上极端速度」，画面会先显示粗层。60–120 km/h 时无积压。
